# Orb Run (dogfood sample game)

Orb Run is a small game built *with* Kinetra to find out where the engine is
pleasant and where it hurts. It is developed in slices; each slice ships with
automated semantic acceptance (no human looking at a screen).

**Rules.** Collect the three orbs, then reach the exit pad before the clock
runs out. The exit stays locked until every orb is collected. All tuning lives
in the `OrbRunRules` component on the `OrbRunManager` entity (time limit,
pickup radius, exit radius, player speed, arena size), so an agent can rebalance
the game with one `entity.patch` and no code change.

## Layout

| File | What it is |
| --- | --- |
| `src/ids.ts` | Stable ids (`stableId`), script ids, semantic actions, gameplay events. |
| `src/authoring.ts` | The authoring plan: the exact MCP tool calls (`scene.create`, `entity.create`, `entity.patch`) that build the game from an empty project, plus `createOrbRunProject()` which replays the same plan through the typed `CommandBus`. |
| `orb-run.kinetra.json` | Canonical project snapshot. The MCP-authored file and the command-bus project must both equal it byte for byte. Regenerate with `pnpm --filter @kinetra/example-orb-run snapshot` after changing the plan. |
| `src/scripts.ts` | Gameplay scripts (`OrbRunPlayer`, `OrbRunOrb`, `OrbRunManager`) on the `@kinetra/core` `GameScript` contract, with save/restore validation, and `createOrbRunScriptRegistry()`. |
| `src/simulation.ts` | `HeadlessSceneSimulation`: binds `ScriptHost` to an engine-free runtime transform table so gameplay runs in plain Node at a fixed step. |
| `src/game.ts` | Run summary, a semantic-input playtest bot (`walkTo`), the winning route, save capture/restore. |
| `src/acceptance-probe.ts` | `OrbRunHeadlessProbe`: a `@kinetra/verification` `RuntimeProbe` over the headless simulation, so the engine's `AcceptanceRunner` runs Orb Run manifests in plain Node (virtual fixed-step time; frames/vector input/other scenes fail loudly). |
| `src/replay.ts`, `src/replay-fixtures.ts`, `acceptance/replays/*.replay.json` | Input replays: `OrbRunReplayRecorder` / `recordOrbRunReplay`, `playOrbRunReplay`, strict `parseOrbRunReplay`, `digestOrbRunState`; the golden `win` / `timeout` recordings come from the playtest bot. |
| `acceptance/*.acceptance.json` | Gameplay contracts as engine `AcceptanceManifest`s: `win`, `timeout`, `save-load`, `audio`, `hud`, `hud-timeout`, `animation`, `assets`, `level`, `navigation`, `replay-win`, `replay-timeout`. |
| `src/hud.ts` | HUD contract: `computeOrbRunHud` (pure state → JSON model), `buildOrbRunHud`, `renderOrbRunHudText`, `formatClock`, `compassFor`. |
| `src/locomotion.ts`, `src/foot-ik.ts` | Pure animation contracts: speed-driven locomotion blend space and two-bone foot placement (`planFootPlacement`). |
| `src/animator.ts` | `OrbRunAnimator`: per-step read-only observer of the simulation that drives the locomotion blend and foot IK from real gameplay movement (`state.animation.*`). |
| `src/assets.ts` | Asset pipeline content: synthetic GLB models, `AssetRecord`s with provenance, Orb Run GLB/WAV importers, an in-memory file system, `buildOrbRunAssets()` / `validateOrbRunAssets()`. |
| `src/hot-reload.ts` | Headless `RuntimeReloadTarget` (`OrbRunReloadTarget`) + `createOrbRunHotReload()`: Orb Run art edits through the engine's `AssetHotReloadCoordinator`, with injectable runtime faults. |
| `src/acceptance-suite.ts`, `src/acceptance-cli.ts` | `runOrbRunAcceptanceSuite` + the `acceptance` script: run every `acceptance/*.acceptance.json` headless, one report, exit code (Node-only, not in the package entry). |
| `src/level-check.ts` | `analyzeOrbRunLevel(project)`: static check of the authored level (structure, reachability, clock vs. shortest route) with structured diagnostics; `walkStraightTo` in `src/game.ts` is the eight-direction bot it predicts. |
| `src/walls.ts` | Walls as project data: `OrbRunWall` component `{ halfWidth, halfDepth }` on any entity with a `Transform`, `readOrbRunWalls`, circle-vs-rectangle `circleHitsWall` / `resolveWallMotion` (the player slides along walls), `orbRunWallComponents` (the `entity.create` payload). The shipped level has none. |
| `src/navigation.ts` | `planOrbRunRoute(project)`: bakes a `@kinetra/navigation-recast` navmesh from the arena + walls and returns the shortest walkable route over every orb to the exit (`route_blocked` when walls close something off, `navmesh_error` with the original message when the navmesh itself fails); `followOrbRunRoute` is the semantic-input bot that walks it. Node-only, not in the package entry. |
| `src/fuzz.ts` | Seeded input fuzzing: `driveOrbRunFuzz`, `OrbRunInvariantMonitor` (per-step invariants), `runOrbRunFuzz` / `runOrbRunFuzzCampaign` (+ replay determinism and save/resume equivalence), `checkOrbRunSaveResume`. |
| `src/base64.ts` | Portable strict base64 (`encodeBase64`, `decodeBase64`, `isBase64`): the entry never touches `Buffer` (guarded by `test/entry-portability.test.ts`). |
| `src/audio.ts` | Audio asset ids, synthetic WAV bytes, the `master/music/sfx` mixer, and `HeadlessAudioService` (records cues, simulation-clock playback). |
| `test/` | `authoring.test.ts` (MCP + command bus), `gameplay.test.ts` (win/lose/clamp/determinism/save), `acceptance.test.ts` (manifests on `AcceptanceRunner`, negative cases). |

## Slices

1. **Slice 1: authored over MCP, playable headless.** Proof:
   - authored from an empty project through the real MCP server over the in-memory transport, one revision per tool call with `expectedProjectRevision`; the file written by `FileProjectStore` equals `orb-run.kinetra.json`;
   - `entity.query` with field selection finds every scripted entity; stale revisions and duplicate ids fail with `STALE_REVISION` / `ENTITY_ALREADY_EXISTS` and leave the file untouched; a rules patch is undone back to the original bytes;
   - the playtest bot wins with semantic input only (`player.move*`), orbs are collected once each in route order, the exit unlocks after the last orb, and the finished run freezes input and clock;
   - reaching the exit early does not win; idling loses exactly once; the player is clamped to the arena; two runs with the same input are identical;
   - a run saved mid-way, JSON round-tripped and restored into a fresh simulation finishes with the same outcome; corrupt saves are rejected without state changes;
   - patching `OrbRunRules.timeLimitSeconds` to 5 through the command bus makes the same route lose.

   Not proven yet: rendering, the Electron player, packaged builds.
2. **Slice 2: acceptance as engine manifests.** `acceptance/{win,timeout,save-load}.acceptance.json` run on `AcceptanceRunner` through `OrbRunHeadlessProbe`. Proof: every step of every manifest passes; a missing path gives a structured `missing_path` diagnostic; screenshot steps fail (no renderer) instead of passing; corrupt saves fail `save.load` without touching the running game; a 5 s clock patched through the command bus makes the *same* win manifest fail at the third-orb check; a typo'd script id fails `assert.logAbsent`.
   Snapshot paths: `state.game.<status|collectedCount|totalOrbs|exitUnlocked|elapsedSeconds|remainingSeconds|step>`, `state.entities.<Name>.position.<i>` / `.script.*`, `state.events.<orbCollected|exitUnlocked|won|lost>`, `state.paused`.
3. **Slice 3: locomotion blend space.** `src/locomotion.ts`: a pure 1D blend space (idle/walk/run at 0 / 1.5 / 4 m/s) on `@kinetra/animation`, driven by horizontal speed. Proof: valid definition, exact weights at sample speeds, blended weights sum to 1, negative speed clamps to idle.
4. **Slice 4: foot placement with the engine's two-bone IK.** `src/foot-ik.ts` (`planFootPlacement`): lowers the pelvis to the lowest foot's ground, then solves both legs with `solveTwoBoneIk`, knees forward. Proof (pure contract, no renderer): flat ground plants both ankles with exact bone lengths; a step plants only that foot higher; a drop-off lowers the pelvis by exactly the drop; a ledge out of reach reports `reachable:false`/`converged:false` and the leg stretches toward it; deterministic; non-finite input throws. Not proven: applying the solved pose to a real skinned model in the player (needs #79).
5. **Slice 5: audio cues.** `src/audio.ts`: deterministic synthetic WAV clips (pickup pitch ladder C5/E5/G5, exit chime, win, lose), a `master → {music, sfx}` mixer on the engine's `AudioMixerModel`, and `HeadlessAudioService` (a `GameScriptAudioService` that records cues and derives playback progress from the simulation clock). `OrbRunManager` plays cues through `context.audio` on the sfx bus (fire-and-forget; a refused play is an `orbRun.audioFailed` warning, never a crash). Proof: a winning run plays exactly pickup 1, 2, 3, chime, win in step order at the authored gains (sfx 0.9 × instance gain); a timeout plays only the lose cue and a finished run is silent; a muted sfx bus still starts cues but at effective gain 0 without affecting gameplay; restoring a save replays nothing and the ladder resumes from the saved count; a service that refuses everything leaves the run winnable. `OrbRunHeadlessProbe` now implements `audio.play/stop/setBusGain/setBusMuted` (refusals throw so manifests fail loudly), reports `state.audio.<playedCount|played.<assetId>|failedCount|cues.<n>.*|buses.<id>.*|playbacks.<n>.*>` and `audio.played` logs; `acceptance/audio.acceptance.json` asserts all of it on `AcceptanceRunner`. Not proven: real decoding/Web Audio output in the player (needs #79), mixer state across a save/load (a fresh simulation starts with the authored mixer).
6. **Slice 6: HUD contract.** `src/hud.ts`: `computeOrbRunHud` is a pure function of the run summary + authored rules + target positions and returns a plain JSON model (`objective`, `orbs`, `timer`, `exit`, `marker`, `banner`); `buildOrbRunHud(simulation)` feeds it from a running headless game (rules read from the authored `OrbRunRules` component). Timer: `m:ss` rounded *up* (never `0:00` with time left, immune to 1/30 s float drift), `fraction` of the limit, urgency `normal` → `warning` (≤ half the clock) → `critical` (≤ 5 s) → `expired`; a won run stays `normal`. Marker: nearest uncollected orb, then the exit once every orb is in (distance in metres, clockwise bearing from forward `-z`, 8-point compass; ties break on entity id so it never flickers); none when the run is over. Banner: win/loss title + subtitle. Proof: pure unit tests for every threshold; the opening HUD of the authored game is exact (`Orbs 0/3 | 0:20 | Exit locked | Orb SE 5.7 m`); a full winning run tracks orbs/objective/marker and freezes with the banner; an idle run walks `normal → warning → critical → expired` and shows the loss; a HUD rebuilt from a JSON round-tripped save equals the saved one; a 60 s clock patched through the command bus reads `1:00`. `OrbRunHeadlessProbe` now exposes `state.hud.*`; `acceptance/hud.acceptance.json` (winning route) and `acceptance/hud-timeout.acceptance.json` (idle until the loss) assert it on `AcceptanceRunner`, and an 8 s clock fails the first timer check. Not proven: drawing the HUD (needs a UI layer in the player, see engine requests) and the Electron player (needs #79).
7. **Slice 7: content through the asset pipeline.** `src/assets.ts`: three deterministic GLB models (orb, exit pad, runner; `createSyntheticGlb`) and the six audio cues are registered as `AssetRecord`s with `kinetra-synthetic` provenance and imported by the engine's own `AssetReimportService` onto an in-memory file system (`MemoryFileSystem`), with an Orb Run GLB importer (header check + `normalizeGlb` + authored dimensions/polycount/bounds) and a WAV importer (RIFF/WAVE check, sample rate). Proof: every first import writes exactly one artifact and the whole database validates with zero diagnostics (`validateAssetRecord` plus an artifact-exists check); two independent builds give byte-identical databases and artifacts; a second import is a no-op with zero writes; an artist edit to the orb source reimports only the orb (new fingerprint, others untouched, `reimportStarted → reimportSucceeded`); a truncated source fails the reimport, keeps the last good artifact and the old record, leaves no temp file, and heals once the source is restored; a non-WAV audio source and a wrong sample rate are refused / warned; synthetic content claiming an external provider or creative-unit cost is flagged by the provenance validator; every audio cue the scripts play is a registered asset. Not proven: loading these assets in the player (the scene still uses primitives; needs #79), disk I/O and the file watcher/hot-reload coordinator, textures.
8. **Slice 8: the runner animates from gameplay.** `src/animator.ts` (`OrbRunAnimator`) subscribes to a new read-only `HeadlessSceneSimulation.onStep` hook and, after every fixed step, turns the player's horizontal speed into a smoothed speed (first-order, 0.12 s) → the slice-3 locomotion blend space → the slice-4 foot placement on a pluggable `GroundHeightFn` (flat by default). It only reads transforms: a pose it can't compute (a ground function that throws or returns NaN) is counted in `failedCount`, logged as an `animation.failed` warning and the last good pose is kept, while the run stays winnable. Nothing of it is saved; a restored save restarts it from rest. Proof: at rest the runner is idle with both ankles planted and the pelvis at standing height; holding a move action walks it through `idle → walk → run` (4 transitions with the release back to idle, weights always sum to 1); on a full winning run the feet stay planted with exact bone lengths at every step and the frozen post-win player settles on idle; two runs give identical pose traces; a step-up plants only the higher foot higher and never lowers the pelvis, a drop-off lowers it by exactly the drop, a 2 m ledge is reported `reachable:false` without stretching a bone; a restored save is not read as a teleport. `OrbRunHeadlessProbe` exposes `state.animation.*` (and takes `{animation: {ground}}`), and `acceptance/animation.acceptance.json` asserts the whole arc on `AcceptanceRunner`. Not proven: driving a skinned model (no `AnimationGraph` runtime sampler is exposed headless, see engine requests) and the Electron player (needs #79).
9. **Slice 9: the content is part of the acceptance gate.** `OrbRunAssetCatalog` (in `src/assets.ts`) wraps the slice-7 pipeline: it imports every asset once, tracks a revision per asset and the last import failure, and `replaceSource(id, bytes)` writes an artist's new source and reimports it. `OrbRunHeadlessProbe` now implements `registerAsset` (the `asset.register` step and `runtime.start.assets`; an unknown asset id or invalid base64 throws so a typo'd manifest fails) and reports `state.assets.<count|modelCount|audioCount|importedCount|failedCount|errorCount|warningCount|reimportCount|unregisteredCues|byId.<assetId>.{kind,importStatus,revision,fingerprint,sourceHash,importedPath,bytes,polycount,dimensions.<n>,sampleRateHz,durationSeconds,error}>`, the metrics `assets.count`/`assets.failures`, and an `asset.reimportFailed` warning log (kept after `stop()`). `acceptance/assets.acceptance.json` (generated by `pnpm --filter @kinetra/example-orb-run snapshot`, fingerprints/hashes as literals, drift-guarded by a test) asserts: everything shipped is imported and valid with exact metadata; the game plays a pickup; an edited orb hot-reimports (revision 2, new fingerprint and hash, game state untouched); a corrupt player source fails the import but keeps revision, fingerprint and artifact (`importStatus: failed`, validator errors stay 0); the good source heals it as a no-op; the run is still won with five cues, every one backed by a registered asset. Not proven: a renderer reloading the changed model (no headless `reloadAsset` in the engine, see engine requests), disk I/O and the file watcher.
10. **Slice 10: replays and a gameplay regression gate.** `src/replay.ts`: a run is its fixed step plus the semantic actions held on each step, so a replay stores only the *changes* of the held set (`inputs`), a SHA-256 digest of the gameplay state every 30 steps (`checkpoints`: step, run summary, runtime positions, every script's state, the event log and the audio cues; animation and HUD are deliberately not in it) and the `outcome`. `OrbRunReplayRecorder` observes a fresh simulation through `onStep` (new read-only `heldActions()`); `playOrbRunReplay` parses untrusted JSON strictly (`OrbRunReplayError` with `code` + JSON `path`: unknown fields/actions, out-of-order inputs or checkpoints, bad digests, missing final checkpoint, another step size), replays it on a fresh game and reports `verified`, the *first diverging checkpoint* and any outcome mismatch. `acceptance/replays/{win,timeout}.replay.json` are the golden recordings made by the playtest bot (regenerate with `pnpm --filter @kinetra/example-orb-run snapshot` after an intended gameplay change). Proof: recording is byte-deterministic and survives a JSON round trip; the committed files replay `verified` *and* equal a fresh recording (no stale digest); dropping the first input diverges exactly at the first checkpoint; shifting one input by one step is caught; halving `playerSpeed` through the command bus breaks the winning recording and names where; the headless probe fed the same inputs ends on the same digest, which `OrbRunHeadlessProbe` now exposes as `state.replay.{step,digest}` so an `AcceptanceManifest` can pin a whole run to one value; 25 malformed or hostile replays are refused with the right code and path. Not proven: the same recordings in the Electron player (needs #185), float equality across CPU architectures (only plain IEEE `+`/`*`, but checked on x86-64 Linux only).
11. **Slice 11: replays as manifests, wider digest, non-blocking playback** (reviewer follow-ups of slice 10). `createOrbRunReplayManifest(replay, suite)` turns a recording into an `AcceptanceManifest`: it re-presses the recorded held sets through `input` steps, advances with `runtime.step` and pins `state.replay.{step,digest}` at *every checkpoint* plus the outcome, so the engine's own `AcceptanceRunner` fails a changed game at the first checkpoint that moved (`acceptance/replay-{win,timeout}.acceptance.json`, generated by `snapshot` next to the recordings, drift-guarded by a test). `digestOrbRunState` now hashes the runtime position of *every* entity (new `HeadlessSceneSimulation.positions()`), not only the scripted ones, so a moved prop or camera changes the digest (the golden recordings were regenerated). `playOrbRunReplay` yields to the event loop every `ORB_RUN_REPLAY_YIELD_EVERY_STEPS` (2048) steps and takes `maxSteps` (`replay_too_long` before any step runs) and an `AbortSignal` (`aborted`), so a 360k-step replay no longer blocks its host. Proof: the committed manifests equal what the golden recordings generate and pass on `AcceptanceRunner`; a halved `playerSpeed` fails the manifest at the digest assertion with the same expected/actual digests the replay player reports; moving the camera changes the digest; a host `setImmediate` loop gets turns during playback; a cap and an abort (before and during) are honoured. Not proven: the manifests in the Electron player (needs #185).
11b. **Review follow-ups of slice 9 (#262, this PR).** The probe's asset catalog no longer leaks across `runtime.start`: every start rebuilds it from the shipped content unless an `asset.register` / `runtime.start.assets` was made while the game was *not* running (that edit is meant for the start that follows), so one `OrbRunHeadlessProbe` can run several manifests in a row and `assets.acceptance.json` passes after a dirty manifest (the old "edit survives a restart" test is replaced by "a plain restart begins from the shipped content"); failure warnings of a discarded catalog stay in `logs()`. `OrbRunAssetCatalog` keeps only the last `ORB_RUN_ASSET_FAILURE_LOG_LIMIT` (256) import failures. README "(this PR)" labels on old slices removed.
12. **Slice 12: one command runs the whole acceptance gate.** `src/acceptance-suite.ts` (`runOrbRunAcceptanceSuite`, deliberately *not* exported from the web-bundled package entry) discovers every `acceptance/*.acceptance.json` by suffix (sorted, non-recursive, so a new manifest can't be forgotten from a hand-kept list), runs each on the engine `AcceptanceRunner` with a fresh `OrbRunHeadlessProbe`, and returns a structured report (`passed`, per-file `steps`/`passedSteps`, the first `failure` step, or an `error.code`: `unreadable`, `invalid_json`, `invalid_manifest`, `probe_threw`, `no_manifests`). An empty or missing directory fails instead of passing vacuously, and one bad file never hides the others. `pnpm --filter @kinetra/example-orb-run acceptance [--json] [dir]` (`src/acceptance-cli.ts`) prints it and exits 0 / 1 (a manifest failed) / 2 (bad arguments), so an agent or a packaged smoke needs one call. Proof: the shipped suite passes (10 manifests, every step green) and covers exactly the files on disk; the known contracts and every golden replay's generated manifest must exist; a false assertion fails with its step index/type; unparsable / wrong-shape / unreadable files, an empty directory and a throwing probe become structured failures; the text report is pinned; the CLI's exit codes are checked in a child process. Not proven: the suite inside the Electron player or a packaged binary.
13. **Slice 13: the authored level is checked before anyone plays it.** `src/level-check.ts` (`analyzeOrbRunLevel`) reads only project data (positions + `OrbRunRules`) and returns `ok`, a `verdict` and structured diagnostics (`code`, `severity`, `entityId`, `message`), so an agent that rebalanced or re-laid-out the level through `entity.patch` finds out *what* it broke. Errors: `scene_missing`, `rules_invalid` (per field), `manager_count`/`player_count`/`exit_count`, `no_orbs`, `transform_invalid`, `orb_unreachable` / `exit_unreachable` (further outside the arena than the pickup/exit radius), `time_impossible`; warnings: `orb_outside_arena`, `player_outside_arena`, `orbs_duplicate_position`, `time_unproven`, `time_tight`. The clock is bracketed: `lowerBoundSeconds` (straight lines between the pickup/exit circles, best order: nothing can win faster) and `playtestSeconds` (what the eight-direction playtest bot needs: octile distance between orb centres clamped into the arena, best of every order up to 8 orbs and greedy beyond with `orderExact: false`, plus one fixed step per leg). A clock below the floor is `impossible`, at or above the bot time `tight` (> 80% used) or `comfortable`, in between `unproven` (no claim). `route` gives the order and waypoints. `walkStraightTo` is the matching bot (up to two move actions at once). `OrbRunHeadlessProbe` exposes `state.level.*` and `acceptance/level.acceptance.json` pins it on `AcceptanceRunner`. Proof: the shipped level is `comfortable` with no diagnostics and exactly `(16 + 8·√2)/4 + 5/30` s for the bot; a real playthrough of the route wins in between the two bounds; patches through the command bus (orb at x=9, exit outside, speed 0, clock 3 s, a clock between the bounds, a clock just above the bot time) give exactly the expected code/entity/verdict; a 6-speed × 11-clock sweep proves every `impossible` loses in the simulation, every `tight`/`comfortable` wins within the predicted time, the verdict never gets worse with more time, and all four verdicts occur; 11 orbs fall back to a greedy order that still wins; the analysis is deterministic and never mutates or throws on bad data. Not proven: that `unproven` levels are winnable or not (analogue input / corner cutting), the check inside the Electron player.
14. **Slice 14: the game is fuzzed with input nobody scripted.** `src/fuzz.ts`: a seeded policy (`driveOrbRunFuzz`; strategies `random` = arbitrary subsets of the four move actions with contradictory pairs, analogue values and idles, `seek` = steer at the nearest objective with fumbles, `mixed`) drives a fresh game for 1200 steps (twice the clock, so finished runs must stay frozen). `OrbRunInvariantMonitor` checks, after *every* fixed step and only through what a player can observe: `status_transition`, `frozen_after_finish`, `collected_monotonic`, `collected_consistent`, `events_consistent` (one pickup event per orb, one unlock, one verdict), `win_preconditions`, `player_in_arena`, `static_entities_still`, `orbs_stowed_when_collected`, `positions_finite`, `clock_consistent`, `audio_consistent` (one cue per pickup + chime + verdict), `animation_valid` (weights sum to 1, legs valid, no failed pose) and `hud_valid` (JSON-safe, banner iff finished, marker only while playing, fraction in [0, 1]). `runOrbRunFuzz({seed})` then proves two cross-run properties on the run's own recording: it replays to the same digests (`replay_deterministic`), and a save taken at a seeded step, JSON round-tripped and restored into a fresh game, finishes in the same gameplay state as the uninterrupted run (`save_resume_equivalent`, `checkOrbRunSaveResume`). A failure carries the seed and the full `OrbRunReplay`, i.e. a complete bug report. Proof: 120 seeds over the three strategies and five rebalanced rule sets (through the command bus) pass with zero violations, the campaign reaches wins, losses and partial pickups; each invariant is shown to fire when the state is sabotaged (teleported player, moved orb/camera, NaN position, rewound clock, un-collected orb) and the violation list is capped. Not proven: invariants over analogue (non-semantic) input, the player in Electron.
15. **Slice 15: art hot-reloads through the engine's own coordinator.** `src/hot-reload.ts` drives the real `AssetHotReloadCoordinator` (`processAssetChange` → `reimportWithDependents` → `updateAsset` + `reloadAsset` on a runtime target → `AssetHotReloadTransaction`) with Orb Run's content on the in-memory file system. The engine only has a `RuntimeReloadTarget` in the Electron player (needs WebGL), so `OrbRunReloadTarget` is the headless stand-in: it validates published bytes like a loader (a non-GLB model is refused), applies them to the entities bound to the asset (`ORB_RUN_MODEL_BINDINGS`: three orbs, exit pad, runner), records what each entity shows (`appliedTo`: asset, fingerprint, bytes hash) and takes injected faults (`refuseUpdate`, `failReload`, `throwOnReload`). `createOrbRunHotReload()` imports everything, loads it as a scene start would, starts the coordinator and offers `editSource(assetId, bytes)` (what the file watcher would trigger). Proof: after scene start every bound entity shows exactly the imported artifact of its asset and loading is not a transaction; repainting the orb gives one transaction (`rebuiltAssetIds` = the orb, old → new fingerprint, reloaded entities = exactly the three orbs, the other seven reported unchanged, exit pad and runner untouched, `reimportSucceeded` before `runtimeReloadStarted` before `runtimeReloadSucceeded`); saving identical bytes is a no-op and a revert is a real change back to the first fingerprint; a corrupt source gives a transaction with `failedAssetId`/`error`, no runtime call, the record and the screen on the last good model (and re-saving the last imported bytes changes nothing); an audio edit reloads with zero affected entities and the new fingerprint is published; a runtime that refuses the bytes / answers `success:false` / throws yields one `runtimeReloadFailed` per attempt, still one transaction each, the screen stays on the old model (the database moves on, so the transaction report is how the drift is found) and the next edit on a healthy runtime catches every orb up; three edits in flight at once run one after the other in call order and end with every entity on the database's fingerprint; and reloading all three models in the middle of a run leaves the gameplay digest unchanged and the run ends on the same digest as an untouched twin. Not proven: a real renderer swapping a mesh (needs #185/#79), the file watcher reading disk, a reload while the game script re-reads the model.
16. **Slice 16: walls, and a route planned on the engine's navmesh.** Orb Run gets obstacles without touching the shipped level: an entity with an `OrbRunWall` component (`src/walls.ts`) is an axis-aligned wall; `OrbRunPlayer` slides along walls (circle of 0.4 m, one axis at a time), `analyzeOrbRunLevel` reports `walls`, `wall_invalid` / `player_in_wall` errors and withdraws its straight-line claim (`walls_present`: lower bound kept, `playtestSeconds` / `route` null, verdict at best `unproven`). `src/navigation.ts` (`planOrbRunRoute`) bakes the arena floor + wall boxes with `RecastNavMesh` (agent radius 0.5 m, a little fatter than gameplay), prices every start -> orb -> exit order with `computePath` and returns legs, polyline, length and clock slack. Proof (`test/navigation.test.ts`, 10 tests): without walls the plan is the Euclidean optimum (27.3 m); with a wall that splits the arena the plan goes round its open end, never enters a wall (sampled every 5 cm), the open-field bot cannot win, and `followOrbRunRoute` wins with all three orbs near the estimate; a walled-in exit gives `route_blocked` naming the exit; plans are deterministic and cell-size independent within 1 m.
   Not proven yet: walls in the Electron player (it has no collision for custom scripts, see #80).
17. **Slice 17: the fuzzer plays on walled levels.** `OrbRunInvariantMonitor` now reads the authored `OrbRunWall` entities (through `getAuthoredComponent`, no new engine API) and checks a 15th invariant, `player_clear_of_walls`: the player's 0.4 m circle never overlaps a wall (resting exactly on a face is legal). Proof (`test/fuzz-walls.test.ts`): seeded campaigns (random / seek / mixed) on three levels built through the command bus (a split arena, a caged exit, scattered pillars) report zero violations; the fuzzer is shown to lean on the walls (many steps spent within 5 cm of a face, never closer than the radius); a walled recording replays to the same digests, resumes from a save at five different steps to the same gameplay state, and does *not* reproduce on the level without the walls; the invariant fires for a player placed inside a wall, stays quiet on the shipped level, and separates a face-touching position from one 1 cm inside.
18. **Slice 18: walls and routes are acceptance state.** `OrbRunHeadlessProbe` takes `{ project, routePlanner }`: with a planner every snapshot carries `state.navigation.*` (the exact `OrbRunRoutePlan` of the probe's project: `ok`, `diagnostics.<n>.<code|entityId>`, `orbIds.<n>`, `legs.<n>.*`, `path.<n>.<x|z>`, `lengthMeters`, `estimatedSeconds`, `slackSeconds`, `orderExact`, `wallCount`; computed once per probe) and `state.level.walls.<n>.*` shows the authored walls. The planner is injected because it loads Recast's WASM: `createOrbRunNavigationProbe()` (in `src/navigation.ts`, Node-only like the suite) plugs `planOrbRunRoute` in, and `runOrbRunAcceptanceSuite` now uses it by default. A probe without a planner has no `state.navigation`, so a manifest that reads it fails with `missing_path` instead of passing on nothing; a throwing planner fails the snapshot. New `acceptance/navigation.acceptance.json` pins the shipped level's plan (27.3 m, 4 legs, 13 s of slack) and plays the first leg. Proof (`test/navigation-probe.test.ts`): the shipped manifest passes on the navigation probe and fails at its first navigation step on a plain one; `state.navigation` equals `planOrbRunRoute(project)` exactly; on a walled project a manifest asserts the wall (`state.level.walls.0.*`, verdict `unproven`, `route: null`), the detour (`state.navigation.lengthMeters`/`slackSeconds`) and that holding `moveRight` for 1.5 s stops the player at the wall face (x = -2.8, within one step of the 0.4 m radius from the face at -2.3), nothing collected; a caged exit reads `route_blocked` naming the exit with `ok: false` and no legs; a manifest quoting the open-field length fails on the wall level at that very step; the planner runs once per probe and navigation never changes the replay digest.
19. **Slice 19: the HUD fails loudly on corrupt state (follow-ups of #205).** `timerUrgency` now checks `won` before the clock, so a run won on the very tick the clock hits 0 reads `normal` with its win banner instead of `expired` (the manager checks the exit before the timeout on the same tick). `computeOrbRunHud` validates its input (`validateOrbRunHudInput` returns every issue at once) and throws `OrbRunHudError` (`code: "ORB_RUN_HUD_INVALID"`, `issues[].field/message`) for a non-finite clock (`formatClock` no longer throws a bare `RangeError` mid-render), a zero/negative `timeLimitSeconds` (the 0/0 `fraction` that serialised to `null`), impossible counts, a bad status, a non-finite player or marker position; `buildOrbRunHud` does the same for a `collectedOrbIds` that is not an array of ids (it used to be a blind cast). Proof: `test/hud.test.ts` (+3 tests, the win-at-expiry one is red on the previous code).
20. **Slice 20: the entry stays portable (groundwork for the Electron player, #79 / #185).** `test/entry-portability.test.ts` walks the *source* import graph from `src/index.ts` and fails if anything reachable uses a Node builtin (`node:*` or a bare `fs`/`path`/...), a Node-only global (`process.argv`, `Buffer.`, `__dirname`, `require(`), a package outside the entry's allow-list (so no `@kinetra/navigation-recast`, `@kinetra/mcp-server`, `@kinetra/input`), or one of the Node-only modules (`navigation.ts`, `acceptance-suite.ts`, `acceptance-cli.ts`, `write-snapshot.ts`). A game module the Electron player bundles can therefore import `@kinetra/example-orb-run` without dragging Recast WASM or the file system into the renderer. The first run of the guard found a real problem: `Buffer.from(...)` in `hot-reload.ts`, `asset-manifest.ts` and `acceptance-probe.ts` (undefined in a renderer). They now use `src/base64.ts` (`encodeBase64` / `decodeBase64` / `isBase64`, strict RFC 4648, equal to `Buffer` at every length 0–300; malformed text throws a `TypeError` instead of being silently skipped). Proof: the shipped graph (20+ files) is clean; the import scanner is checked on static / re-export / type / side-effect / dynamic imports and ignores comments; a sabotaged virtual graph (builtin, Node-only module, forbidden package, Node global, unreadable file) yields exactly those six findings; a Node import in a nested module is found. Not proven: a real bundler run (no bundler in the repo), the Electron player (the pluggable game module of #185 is still open; wire Orb Run in once it merges).
21. **Slice 21: mud (slow zones), authored as data like walls.** An entity with an `OrbRunSlowZone` component `{ radius, speedMultiplier }` (`src/zones.ts`; centre = `Transform.position`, multiplier in (0, 1]) slows the player to `playerSpeed × multiplier` while its centre is inside (boundary included; overlapping zones: the slowest wins). The zone is decided from where the step *starts*, so the rule is a pure function of the previous state and replays stay deterministic. The shipped level has none, so every digest is unchanged; a multiplier above 1 is rejected so the level check's lower bound ("nothing can win faster") and the speed ceiling stay true. A malformed zone throws `OrbRunSlowZoneError` (every issue at once) when the game starts, and is a `slow_zone_invalid` error diagnostic in `analyzeOrbRunLevel`, which for a muddy level keeps the lower bound but withdraws the full-speed playtest claim (`slow_zones_present`, `playtestSeconds` / `slackSeconds` / `route` null, verdict at best `unproven`) and reports `slowZones`. Proof (`test/slow-zones.test.ts`): per-step displacement is exactly `speed × multiplier × dt` by the zone under the step's start; the runner animation walks through mud and runs outside it; the same route wins on open ground and loses on a clock the mud makes too short (the patch costs ~1 s); the fuzzer holds every invariant on a three-patch level and displacement never beats the multiplier of the zone it started in. Not proven: mud in the Electron player, mud in the navmesh route (`planOrbRunRoute` prices the open-field length), an invariant in `OrbRunInvariantMonitor` (it would flag the teleports other tests perform with `restorePosition`).
22. **Slice 22: the route planner prices mud.** `walkSecondsAlong(path, playerSpeed, zones)` (`src/zones.ts`, pure, in the entry) walks a polyline in 1 cm pieces and prices each at the speed of the slowest zone under its midpoint (the boundary counts as inside; no zones is exactly `length / speed`). `planOrbRunRoute` uses it twice: the leg costs that pick the visiting order are seconds instead of metres once the level has mud (so a dry order beats a mirrored, equally long order through a swamp), and `estimatedSeconds` / `slackSeconds` include the mud. The plan gains `mudSeconds` (`estimatedSeconds - lengthMeters / playerSpeed`) and `slowZoneCount` (also on a failed plan), both visible to manifests as `state.navigation.*`. This is the first time a muddy level gets a time claim: `analyzeOrbRunLevel` still withdraws its straight-line playtest claim (`slow_zones_present`, `unproven`). The path itself is still the navmesh's *shortest* walk, so the planner prices mud but does not detour round it. Proof (`test/navigation-mud.test.ts`, 8 tests): pricing unit tests (outside, inside, partial, overlapping, boundary, invalid speed); a dry level keeps its numbers and reports no mud; mud on the middle orb adds exactly the 0.5 s its 2 m cost at half speed; mud on the bottom edge flips the first stop to the dry orb and the rejected order is priced 0.75 s slower; a bot following a muddy plan wins within the estimate window and is slower than on dry ground; a lake plus an 8 s clock gives negative slack and the same bot really loses (the dry 8 s level has slack); a manifest pins `slowZoneCount`/`mudSeconds`/`estimatedSeconds` on the navigation probe and the dry level fails it at the mud count. Not proven: detouring round mud (needs area costs in the navmesh wrapper, see engine requests), mud in the Electron player. Reviewer follow-ups: `mudSeconds` is clamped to a true `0` on a dry route (summation noise could give `-0`), `walkSecondsAlong` throws `RangeError` for a zone whose multiplier is outside (0, 1], and the greedy order (past `ORB_RUN_ROUTE_EXACT_ORDER_LIMIT` orbs) and repeated path points are tested. Cost: the 1 cm sampling is O(path length / 0.01 × zones) per leg pair, fine for this arena, slow for a very large level.
23. **Slice 23: the fuzzer holds the game to its speed limit (mud included).** `OrbRunInvariantMonitor` gains a 16th invariant, `player_speed_bound`: in one fixed step the player covers at most `playerSpeed × multiplier × dt`, where the multiplier is the slowest `OrbRunSlowZone` under the position the step *started* at (the rule the player script follows; walls and the arena edge only shorten a step). It reads the speed from the authored `OrbRunRules` and the mud from the authored zones, and only judges steps nothing else touched: a `restorePosition` between two steps bumps `stateRevision` by more than the step's one, so a teleport is not reported as a speed violation (it still trips `player_in_arena` / `player_clear_of_walls`). The monitor takes `{ slowZones }` to be held to an *intended* level instead of the observed one, which is how a game that ignores its mud is shown to be caught. Proof (`test/fuzz-speed.test.ts`): winning runs on open and muddy levels are clean; a rebalanced `playerSpeed` of 9 moves the ceiling; with an expected 1 m patch round the start the monitor reports exactly the steps that started inside it (the first at step 1, message naming `4 m/s x 0.4`) and nothing else; teleports are skipped and the step after is judged from the new spot; every existing fuzz campaign (including the muddy and walled ones) now runs with the invariant on and stays at zero violations. Not proven: speed under analogue input beyond what the fuzzer drives, mud in the Electron player.
24. **Slice 24: portability is checked across package boundaries.** `test/transitive-portability.test.ts` continues where slice 20 stopped: it follows every `@kinetra/*` import from the entry into that package's `src/index.ts` (barrel) and attributes each Node builtin to the engine package that imports it. Rules: the packages that are clean today (`core`, `command-bus`, `project-model`, `audio`) must stay clean transitively; the Node-builtin set of every other engine package the entry reaches may only shrink (`NODE_DEBT` is an upper bound per package, so a new `node:*` import in `animation`, `asset-pipeline` or `verification` fails the *game's* test even though the engine's own tests do not care). The ledger is what a bundler for the Electron renderer would trip over (engine request: split Node-only code out of the barrels of `@kinetra/asset-pipeline`, `@kinetra/verification`, `@kinetra/animation`). Proof: the walk reaches the five expected engine packages and never `navigation-recast`; a sabotaged virtual tree shows builtins attributed to the owning package, barrels followed, third-party imports ignored, unreadable sources reported. Not proven: an actual bundler run; dynamic specifiers.
25. **Slice 25: saves are untrusted input (all or nothing).** `restoreOrbRunSave` used to apply positions first and scripts one by one, trusting the file: a corrupt script state left the player already teleported, and nothing stopped a save from putting the player outside the arena or inside a wall, from carrying a manager that says "won" with no orb collected, or from naming entities the level does not have. `src/save-validation.ts` (`validateOrbRunSave`, `OrbRunSaveError` with `code: "ORB_RUN_SAVE_INVALID"` and `issues[].path/message`, every problem at once) now runs first: exact envelope (schema 1, no unknown fields, integer `step`), exactly the entities a capture produces, each script's own `validateRestoreState`, positions that are finite and where the game can put them (player inside the arena, outside every wall, at its authored height; everything else where it was authored; a collected orb stowed, a waiting one not), and one story across scripts (won ⇒ exit unlocked and every orb collected; playing ⇒ inside the time limit; lost ⇒ the limit used; manager and orbs agree; the player is frozen exactly when the run is over). If applying a validated save still fails, the state captured just before is put back. Proof (`test/save-hostile.test.ts`): saves taken after *every* step of 36 fuzzed runs are accepted (no false rejections); a won run's save restores into a finished game; ~45 hostile saves are refused with the exact issue paths and leave the game byte for byte unchanged (same capture, same `stateRevision`); an open-level save is refused on a walled level (face contact legal, 1 cm inside not); a restore that throws half way is rolled back. Not proven: saves across different levels beyond walls (orb count, rules), the `step` field (fixed in slice 26).
26. **Slice 26: quick-load moves the clock with the state.** Slice 25 left a gap its own "Not proven" named: `restoreOrbRunSave` into a simulation that had already advanced restored positions and scripts but left `simulation.step` where the abandoned run stopped, so the saved state (`elapsedSeconds` inside the manager) and the simulation clock (`step`, `elapsedSeconds`, the audio clock, the `step` stamped on later logs/events/cues, `summarizeOrbRun().step`) described two different moments. Loading only worked "right" for callers that remembered to `restoreStep` on a fresh simulation first (the probe's `save.load` and four tests did). `HeadlessSceneSimulation.restoreStep` is no longer limited to a fresh simulation, and `restoreOrbRunSave` applies the save's `step` first, so the rollback of a failed restore puts the previous clock back too. Existing callers are unaffected (same value twice). Proof (`test/quick-load.test.ts`): after a quick-load from the end of a won run back to a mid-run save, `step`, `elapsedSeconds` and the run summary equal the save's and `capture(restore(save))` equals the save byte for byte; playing the rest of the route from there reproduces the first timeline exactly (same final capture, step included); for 12 fuzzed runs, restoring an earlier save into a run that went 200 steps further is the identity; loading a later save into a fresh game jumps the clock forward, a refused save leaves the clock alone; `restoreStep` takes any non-negative integer and refuses the rest. Not proven: cues/logs/events recorded on the abandoned timeline are kept (they keep the step they were recorded at), and the animation restarts from rest as before.
27. **Slice 27: saves from another level, and a "won" save that says where the player is.** The manager writes derived numbers next to its real state (`totalOrbs`, `collectedCount`, `remainingSeconds`); a restore ignores them, so a save written for a level with another time limit loaded silently and a hand-edited counter went unnoticed. `validateOrbRunSave` now holds them to the loaded level: `totalOrbs` is this level's orb count, `collectedCount` is the length of `collectedOrbIds`, `remainingSeconds` is `max(0, timeLimitSeconds - elapsedSeconds)` of *this* level's `OrbRunRules` (to within 1e-9 s, so float noise from another build's addition order is not "tampering"; a non-number is refused) (each problem on its own `scripts.<manager>.<field>` path, a missing field included). A `won` save must also have the player at the exit: within `exitRadius` plus the one step the player may still take on the winning tick (`playerSpeed x fixedDeltaSeconds`), otherwise `positions.<player>` is refused. Proof (`test/save-other-level.test.ts`): a 90 s level's save is refused on a 45 s level and the other way round (own-level saves accepted); each hand edit is refused with its own path, all three at once are all reported, a lost run keeps `remainingSeconds` at exactly 0; the real winning save is accepted, the player at the exit's edge of reach is legal and 1 cm beyond is refused, and the same far position is fine while the run is still playing; the existing 36-run x 800-step sweep still accepts every save a real run produces (no false rejections). Follow-up (slice 28, from review): the tests read `exitRadius` / `playerSpeed` from the level's rules instead of hard-coding 1 and 4, and a won save whose player position is absent or not a finite `[x, y, z]` is locked as refused (by the position rule). Not proven: the won-save reach assumes `playerSpeed` is the fastest the player ever moves (mud only slows; a boost or dash would widen it); orb *positions* from another level are already caught by the static-entity rule; a level with a different number of orbs cannot be authored yet (the orb ids are fixed constants).

## Engine requests found while building this

Filed as GitHub issues labelled `dx`: #79 (player can't load a second game), #80 (headless simulation, component access, script queries, MCP test client), #81 (component payload validation); label `bug`: #122 (`AcceptanceRunner` passes steps whose optional probe method is missing).

- No engine-owned headless simulation: the player binds script transforms to `THREE.Object3D` positions, so gameplay can't run in Node without a renderer. `src/simulation.ts` is a stop-gap that could move into `@kinetra/core`.
- `GameScriptContext` can't read the entity's authored components, so tuning data (`OrbRunRules`) has to be read from the project by the script factory.
- No scene query by component or script (`findEntityByName` only), so the manager gets its orb list from the factory.
- The Electron player hard-codes the Arena scripts and boots `createArenaProject()`; there is no way for an example package to register its scripts and project.
- No exported MCP test client; tests copy a JSON-RPC shim from `packages/mcp-server/test`.
- `AcceptanceRunner` silently passes `save.*`, `runtime.pause/resume`, `animation.*`, `audio.*`, `navigation.*` steps when the probe lacks the method (#122); there is no engine headless `RuntimeProbe`, so `src/acceptance-probe.ts` is a stop-gap.
- No headless audio: `apps/player`'s `AudioController` is bound to Web Audio and `@kinetra/audio` only has the mixer model, so verifying "which cue played at what gain" in Node needs a service like `HeadlessAudioService` (`src/audio.ts`) that could move into `@kinetra/audio`.
- `GameScriptAudioService` only has `play`; scripts can't `stop`, set bus gain/mute or read playback state, so a game can't implement e.g. a pause-duck or "stop music on win" through its context.
- Component payloads (`Primitive.kind`, `Transform` shape) aren't validated at the command-bus boundary; a bad `Primitive.kind` only fails when the renderer instantiates it.
- The asset pipeline's `passthrough` importer carries no audio metadata, so audio can't use it; there is no audio importer at all. Orb Run brings `OrbRunWavImporter` (`src/assets.ts`: walks the RIFF chunks, requires an integer-PCM `fmt ` (plain, or `WAVE_FORMAT_EXTENSIBLE` with a PCM sub-format; whole-byte bit depths only) and a non-empty `data` chunk that fits the file, reads the sample rate from `fmt `, so a `LIST` chunk before `fmt ` no longer yields a wrong rate) and `OrbRunGlbImporter`, which records the dimensions *measured* from the geometry (`measureGlbDimensions`) and warns `orbrun.model.sizeMismatch` when `recipe.settings.size` disagrees (`orbrun.model.unmeasured` + declared size when nothing can be measured; `orbrun.model.invalidDeclaredSize` when the declared size is not three finite non-negative numbers). Both could move into `@kinetra/asset-pipeline`. `MemoryFileSystem.readFile` returns a copy, like `writeFile` stores one.
- No headless animation sampler: `AnimationGraphMachine`, blend spaces and IK are pure contracts, but nothing in the engine turns "blend weights + clips + skeleton" into a pose without Three.js `AnimationMixer`, and although `GameScriptContext.animation.graph.setParameter` exists, only the Electron player implements it, so a headless script has no animation service to talk to. Orb Run's `OrbRunAnimator` is therefore an external observer of movement rather than something a script drives; an engine-owned headless `GameScriptAnimationService` (graph parameters + a pose evaluator over clips and skeleton) would let the same blend/IK be asserted through the scripts' own API on real clips.
- No traversal cost in `@kinetra/navigation-recast`: `computePath` returns the shortest walk, with no per-area cost (mud, water) and no way to mark a polygon area at bake time, so `planOrbRunRoute` can price mud (`walkSecondsAlong`) but not route round it. Area flags/costs on `RecastNavMesh.bake` + `computePath` (Recast's `dtQueryFilter`) would let the plan choose the fastest path instead of the shortest.
- No UI/HUD layer contract: the player only has a fixed shell overlay (`apps/player/src/shell.ts`), so a game can't declare HUD widgets and have the player draw them from state. `src/hud.ts` defines its own JSON HUD model; a draw-from-model contract in the player would let the same `state.hud` drive the real overlay.
